# V3 审查：高分 V2 与 LIBERO long

审查日期：2026-10-09。用户报告 V2 总分 96.7，失败主要集中在 LIBERO long。
本次未拿到对应 checkpoint、逐任务结果或失败视频，因此不能把失败归因于某种特定机制。
结论基于本地实现、受控张量实验与接口回归测试，不是新的 LIBERO 成功率结论。

## 结论

目前 V3 是可微延迟反馈记忆的三帧验证版，还不足以作为已经针对 long 任务设计完成的升级。
因果顺序和状态管理基本成立；但只训练一次更新、在线多次积累、仅视觉损失和长 horizon
使用方式存在关键缺口。修复实现错误后，也不能据此认定 V3 能保持或超过 96.7。

## 尚未解决的设计缺口（按优先级）

### P1：训练的记忆状态分布与整局推理不一致

`QwenResidualWorldInverseV3.forward_ttt()` 首次调用 `step_encoded()` 不传 state，
每个样本都从 W=0 开始，只有第二次调用能结算一次反馈。在线 `predict_action()` 则不断
传回之前的 Fast Weights。共用 `write()` 公式不能消除这个差异。

这意味着训练没有覆盖非零 W 的关联记忆更新，也没有训练旧记忆与新阶段的竞争。
初次写入时 rho*W 和 W*k 都为零；仅调节 forget_factor 无法在三帧训练中学到遗忘效果。
本地 LIBERO_10 评估上限 520 步、动作块 8 步，约有 64 次反馈。

受控反例：固定单位同向 key/value、eta=.01、rho=.995 时，单方向递推为
`w[n+1]=.985*w[n]+.01`。真实 `write()` 可复现 `w[64]/w[1]≈41.325`。
它说明在线状态幅度可以远离单次训练分布；不是声称真实 rollout 必然放大 41 倍，
也不是数值发散（该例有有限定点）。现有 1000 次 finite/norm 测试不能排除此问题。

需要：连续锚点训练、积累历史的 burn-in、多步后续损失、TBPTT；最终评估完整长轨迹。
不建议未经实验靠重置频率或任意裁剪把这个问题隐藏掉。

### P1：视觉预测误差更小不保证动作成功率更高

当前 loss 只有 `(adapted_delta - (zf-zm))^2`，所有动作模块冻结且不参与这个 loss。
原有 Action Head 使用的是 V2 训练得到的条件分布。一个降低视觉 MSE 的 correction，
仍可能改变抓取、释放或放置所需的条件；空间平均误差也可能偏重背景和大面积变化。

尤其世界模型没有输入实际执行的动作；在线反馈同时混合了动力学偏差、动作执行偏差、
策略走错阶段以及不可预测的变化。如果基线表示的是任务期待的运动，实际失败产生的误差
不一定应该成为下一步的“正确运动”。这是一项需要闭环验证的风险，不是已经观测到的失败原因。

后续若加入动作目标，应从真实中间帧读取对应的 action/state，而不是复用原始帧的动作。
冻结 Action Head 的参数不妨碍梯度通过它回传记忆。可以比较动作监督与保守的条件漂移惩罚；
不建议立即联合更新已有高分骨干。必须用同一批初始状态比较真实 LIBERO 成功率。

### P1：short_long 模式的长 horizon 没有同等训练

三帧配置只覆盖 K→K 的反馈训练，默认 K=8；`predict_action()` 的 short_long 模式同时
对 8 和 80 读取、入队。从第 80 帧起，短/长预测可能一起到期，`write()` 会按所有 token
求平均。此时短期反馈的权重比例也发生变化，不只是多了一个输出分支。

需要二选一：首轮实验只修正短分支、长分支维持 V2；或者训练时包含相同的长 horizon、
到期队列和多反馈聚合。当前代码仍保留两个 horizon 的接口，本次未擅自改变其语义。
LIBERO long 是任务持续时间/阶段复杂度的问题，不等于一定要打开 short_long 条件模式。

### P2：目前缺少显式任务阶段与反馈可信度控制

记忆读取使用当前视觉、均值池化语义、预测残差、视角位置和 horizon，
能够学习隐式关联，但没有显式的子任务进度、完成状态或阶段切换判断。
全局标量 gate 对不同观测不作可信度选择；查询相似性可间接选择历史，但不保证过滤错阶段反馈。

rho=.995 的纯衰减项经过 64 次反馈仍保留约 72.6%，半衰期约 138 次（8 帧间隔约 1106 帧）。
完整 delta-rule 还有误差校正项，因此这不是实际记忆寿命的精确估计。
如果失败表现是漏做后续步骤、反复回到旧步骤，应该先验证任务阶段条件是否足够；
局部运动误差记忆可能不是首要解决方案。

### P2：语义与空间压缩的取舍

每视角池化到 7x7 后共享 128 维关联记忆，读取经线性 decoder 和插值恢复特征图。
它适合作为低容量纠偏基线，但小物体接触、夹爪释放时刻等细节可能被压缩。
不能把全部失败都解释成“记忆容量不足”，应先看失败阶段与修正空间分布。

## 本次修复的确定实现问题

| 问题 | 修复 | 验证 |
|---|---|---|
| 训练器周期评估未传 step，V3 会报错 | World 专用训练入口复用原训练器，仅把 TTT 周期评估换为因果反馈诊断 | 真实 tiny V3 前向、模式恢复、异常恢复、旧模型分支 |
| correction 在 BF16 相加时可能消失，target 先低精度相减 | correction/残差/loss 差分保留 FP32，动作入口才转换 | sub-ULP 非零 correction 与梯度；五种条件模式零门控回退 |
| batch 仅部分槽位重复 horizon 未拦截 | 按样本检查重复 | `[8,8]` 与 `[8,16]` 拒绝 |
| V2 action horizon 不是8时仍固定采样8/16 | 从配置继承 K，使用 K/2K，检查范围 | K=4/16、旧字段和非法范围 |
| 显式 LIBERO horizon 非 chunk 整数倍，反馈永远错过 | World 客户端拒绝无法收到目标观测的覆盖值 | chunk8、h12 拒绝 |

FP32 修复保留 V2 原本计算的 base_future 再加 correction，以保证 gate=0 精确回退。
因此公开 absolute future 与 `current.float()+adapted_delta` 之间可能保留 V2 原先的舍入差异；
残差指标与 absolute-feature 指标不应假定在低精度下逐位相等。
动作入口仍使用骨干精度，小到该精度无法表示的 correction 不会改变动作条件，
所以只看 FP32 loss 改善仍不够。

周期日志 `train_feedback/*` 是训练 batch 诊断，不是验证集准确率或 LIBERO 成功率。
训练 `ttt_future_gain` 按残差 MSE 计算，离线同名指标按 absolute future MSE 计算；
二者在 BF16 基线舍入下可能有微小差异，不应据极小差值判断收益。
公共 trainer、V2 和 RoboTTT 原始文件没有因这次修复而修改。

验证结果：模型/记忆与 LIBERO 接口测试共 34 项通过，Python/Shell 语法检查和
`git diff --check` 通过。测试使用小模型与接口替身；本次没有运行实际训练或 LIBERO 仿真。

## 对 96.7 基线的建议顺序

1. 固定 V2 checkpoint、初始状态、任务集合、随机种子与评估设置，复核每个 long 任务和失败阶段。
2. 比较 V2 与 V3 零门控：条件应一致；随机动作生成需要相同噪声才能比较逐步输出。
3. 在失败/成功轨迹上做连续观测回放，记忆只消费已到期反馈，记录随时间的基线/修正误差、
   correction RMS、Fast-Weight 范数和动作条件漂移。单次三帧指标不能替代这一步。
4. 在证明误差反馈有效后，增加连续锚点与多步监督；若使用 long 分支，同步训练同样的队列。
5. 用固定 V2 Action Head 检查动作损失与闭环成功率；先看 long 收益，再确认其他任务集没有回退。

如果主要是局部抓取/接触误差，运动反馈值得继续试；如果主要是阶段遗漏/重复，
优先调查进度条件；如果是接近完成时超时，先检查有效动作推进与停滞，不把 horizon 参数
当作任务完成时间。现在缺少失败视频，尚不能在这些解释之间做定论。
